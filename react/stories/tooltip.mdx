# Tooltip

Text that appears when a user hovers over or focuses an element. It matches the look of the [Optics tooltip](https://docs.optics.rolemodel.design/?path=/docs/components-tooltip--docs).

The CSS tooltip is drawn with pseudo-elements on the element itself. This component is a [Base UI tooltip](https://base-ui.com/react/components/tooltip) instead: the popup is rendered in a portal and positioned with JavaScript, so it is not clipped by overflow and flips away from the edge of the viewport.

**Optics version:** 2.6.1

```sh
npx shadcn@latest add https://docs.optics.rolemodel.design/r/tooltip.json
```

## Props

Wrap a single element in `Tooltip`. That element becomes the trigger, so it must accept a `ref` and props, and should be focusable for keyboard users.

| Prop       | Values                           | Default |
| ---------- | -------------------------------- | ------- |
| `text`     | The tooltip content              |         |
| `position` | `top`, `right`, `bottom`, `left` | `top`   |
| `delay`    | Milliseconds before it opens     | `300`   |

Other props, such as `open`, `defaultOpen`, and `onOpenChange`, go to Base UI's `Tooltip.Root`.

A disabled button does not get pointer events, so its tooltip never opens. Wrap the button in a `span` with `tabIndex={0}` and put the tooltip on the `span`.

```tsx
<Tooltip text="This is a tooltip">
  <span tabIndex={0}>
    <Button disabled>Disabled Button</Button>
  </span>
</Tooltip>
```

## Customizing

The popup does not use the Optics tooltip classes. Its styles live in `tooltip.module.css`, which is copied into your project with the component and built from the same Optics tokens. Edit that file to change the tooltip. See [Tooltip API](https://docs.optics.rolemodel.design/?path=/docs/components-tooltip--docs#tooltip-api) for the values the CSS version uses.
